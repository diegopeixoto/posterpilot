# PosterPilot — Impeccable

Design context for all future work on this project. Keep in sync with `src/app.css`
(theme tokens + component layer) — that file is the source of truth for the actual values.

## Design Context

### Users

Self-hosters / homelabbers running a **single media server** (Plex, Jellyfin, or Emby)
who want to curate poster and backdrop artwork for their library. They're technically
comfortable — \*arr-app, Kometa, Docker/Unraid people — but they come to PosterPilot for
the **visual** job: browse artwork and apply it fast, not wrestle config. Typical context
is a desktop browser on the LAN, often evaluating many titles in a row. The emotional goal
is **confidence** that the right artwork landed, plus the small pleasure of watching their
library look great.

### Brand Personality

**Sleek & cinematic.** Three words: **cinematic, confident, quiet.** The UI is the gallery
frame, not the art — it recedes so posters and backdrops are the hero. Voice is direct and
unfussy, like a good CLI tool that grew a face; never salesy, never cute.

### Aesthetic Direction

- **Reference:** MediUX — image-forward, metadata heroes, spotlight, artwork "sets."
- **Theme:** Dark **by default**. Near-black base (`#0a0a0a`), light text (`#fafafa`),
  `color-scheme: dark`. Darkness makes the artwork pop — but it's the default, not a
  constraint: the **theme-kit engine** (`src/lib/theming/`) ships additional built-in
  themes (including a light one), per-theme customizations, and user-authored custom
  themes. The principles in this document govern the default PosterPilot theme;
  other themes are user opt-outs with their own identity.
- **Tokens:** Components must consume the semantic `--pp-*` tokens (exposed as
  `bg-surface`, `text-text-muted`, `border-border`, `rounded-surface`, … via
  `@theme inline` in `src/app.css`) instead of hard-coded `neutral-*`/`accent-*`
  utilities, so every theme can restyle them. Semantic colors (emerald/amber/red)
  stay fixed — they carry meaning, not theme. Radius goes through
  `rounded-surface`/`rounded-control`, never a fixed `rounded-lg`, or the Terminal
  theme's zero-radius identity and the radius override both stop at the token wall.
- **Scrim vs well:** `bg-scrim` dims what is _behind_ something (dialog backdrops,
  badges over artwork) and stays dark in every theme, light ones included;
  `bg-well` is the sunken inset panel (log boxes, code blocks) and follows the
  theme. Reaching for the wrong one is how a light theme ends up painting a white
  backdrop over a white page.
- **Themes may reskin, not just repaint:** a theme can change component shape and
  affordance through `[data-theme]` rules at the end of `src/app.css` (built-ins) or
  its theme file's CSS field (user themes). The three extreme presets are the
  reference for how far that goes — read them before adding a fourth.
- **Accent:** a single violet (`--color-accent-600: #7c3aed`) in the default theme,
  used sparingly for the primary action, active states, and the MediUX badge. One
  accent, never a rainbow.
- **Surfaces:** subtle — `rounded-surface`, thin `border-border` borders, translucent
  `bg-surface/60` fills. Let imagery carry the contrast, not the panels.
- **Semantic color:** emerald = changed/applied, amber = warn, red = error, neutral = info.
  Reserved for meaning, never decoration.
- **Anti-references — explicitly NOT:**
  - **Not a flashy gamer/RGB UI** — no neon gradients, glow, or aggressive motion.
  - **Not toy-like / overly playful** — no cartoon rounding, bright primaries, emoji-as-UI.
  - **Not a corporate SaaS dashboard** — no generic Material/Bootstrap admin blandness,
    stock charts, or enterprise chrome.

### Accessibility & Inclusion

- Target **WCAG AA** — keep AA contrast for text and controls. Every shipped theme's
  text tokens are held to 4.5:1 on both background and surface by
  `src/lib/theming/theme-contrast.test.ts`, which reads the `[data-theme]` blocks
  directly, so this is enforced rather than promised. A user's own accent override is
  their business, but the accent _foreground_ is re-derived for them so the primary
  button never turns white-on-yellow.
- **Honor `prefers-reduced-motion`** — the View Transitions wired through SvelteKit's
  `onNavigate`, and any other animation, must degrade to instant or a plain cross-fade.
- **Don't ride meaning on color alone** — pair the semantic badge colors with an icon or
  label so color-blind users get the same signal.

### Design Principles

1. **Artwork is the hero; chrome recedes.** Every layout choice gives posters/backdrops
   more room and the UI less. If a control competes with the image, the control loses.
2. **One accent, used sparingly.** Violet marks the primary action / active state only.
   Color anywhere else must mean something — never decorate with it.
3. **Cinematic, not flashy.** Get depth from near-black surfaces and restraint, not glow,
   RGB, or bounce. Calm confidence over spectacle.
4. **Dense where it's work, spacious where it's browsing.** Library and detail views are
   image-forward and breathable; settings and activity stay legible and information-honest
   without collapsing into an \*arr config wall.
5. **AA + reduced-motion are constraints, not afterthoughts.** Contrast and motion-safety
   are part of "done," and no signal depends on color alone.
